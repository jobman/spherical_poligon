# Лаборатория субтайлов

Отдельная сцена `Assets/_Project/Scenes/SubdivisionLab.unity` служит для подбора
плотности без генерации полного глобуса при каждом движении ползунка.

Открыть её можно из игры: **Esc → Подбор субтайлов**, либо через меню редактора
**Spherical Civilization → Open subdivision lab**. В редакторе для работы нужен
Play Mode. По решению пользователя работаем только через редактор Unity;
отдельные exe не собираем.

- Верхний ряд: три реальных шестиугольника, ID 1, 217 и 432.
- Нижний ряд: три реальных пятиугольника, ID 0, 101 и 273.
- Два независимых ползунка задают точное число субтайлов от 12 до 128.
- Все формы показаны в одном масштабе; меньшие родительские тайлы не увеличены
  искусственно до размеров больших. Перспективы и наклона камеры нет.
- Пересчитываются только шесть показанных тайлов, с задержкой 100 мс после
  движения ползунка. Примеры используют тот же генератор, границы и seed, что
  и основной мир. Измеренный пересчёт с построением mesh: около 35–60 мс.

**Сохранить** записывает оба количества и seed в `WorldSettings.json` под
`Application.persistentDataPath`. **Применить к глобусу** сохраняет их и открывает
основную сцену. **Скопировать значения** копирует JSON для передачи в чат.
Перемещение ползунков само по себе не меняет сохранённые настройки мира.

В настройках основного мира также появились два отдельных количества. Общий
размер карты равен `630 * hexagonSubtilesPerTile + 12 * pentagonSubtilesPerTile`.
Старый файл с единственным `subtilesPerTile` продолжает работать: его значение
используется для обоих типов, пока они не сохранены отдельно.

Границы соседних родителей создаются единожды с плотностью, подходящей обоим
владельцам. Проверены крайние пары 128/12 и 12/128, а также 37/24. Все рёбра
имеют двух владельцев, соседство взаимно, граф замкнут и связен. Геометрия
предпросмотра совпала с геометрией тех же ячеек в полном мире.

`BuildPreview` создаёт только выбранные интерьеры, но использует полную
каноническую топологию родительских границ. Его результат предназначен для
рисования и не содержит графа рёбер/соседства субтайлов; игровые системы должны
продолжать пользоваться `OperationalSubdivision.Build`.

Проверены компиляция, геометрия, точные количества, миграция/сохранение настроек
на временных файлах и фактический рендер примеров. Ручная проверка элементов
интерфейса и синтетическое управление ползунками не выполнялись.
